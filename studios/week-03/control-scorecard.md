# Task 4 — Control Scorecard

| Construction | Guarantee and its condition (axis 2) | Failure / bypass | Primitive break vs. misuse |
|---|---|---|---|
| ECB mode | With a secure block cipher and a strong, secret key, conceals individual block contents but reveals block equality. It does **not** guarantee confidentiality of message structure. | Identical plaintext blocks under the same key produce identical ciphertext blocks, exposing repeated regions and patterns. Leakage is silent. | **Misuse:** choosing ECB when message confidentiality requires hiding patterns; no primitive break. |
| CBC / CTR | Message confidentiality against passive attackers **if** the cipher is secure, the key is strong and secret, and mode limits are respected. **CBC:** use a fresh, unpredictable IV for each encryption. **CTR:** never repeat a nonce/counter input under the same key, including through counter wraparound. Neither mode alone authenticates messages. | CTR reuse gives `c1 XOR c2 = m1 XOR m2`; known plaintext recovers the other plaintext over the known overlapping portion. Predictable/reused CBC IVs undermine its confidentiality guarantee. These modes can also be modified without built-in detection. | **Misuse:** violating IV/nonce conditions or treating encryption as authentication; no primitive break. |
| `H(secret‖msg)` MAC | Claims authentication, but a secret key alone does **not** make this construction a secure MAC when the hash permits length extension, as in the lab. | An attacker with a message, tag, and known or guessed secret length resumes hashing to forge a tag for `msg‖glue-padding‖extension`. The verifier accepts the forged bytes without the attacker knowing the key. | **Misuse:** using an extensible secret-prefix hash as a MAC; the attack requires no primitive break. |
| HMAC | Message authentication and integrity, resistant to this length-extension attack, **if** a suitable hash such as SHA-256 is used with a strong secret key, adequate tag length, and correct verification of all protected bytes before acceptance. Provides neither confidentiality nor replay prevention by itself. | No successful HMAC bypass is demonstrated here. A disclosed/guessable key permits forgery; skipped verification permits tampering; accepting a replay without freshness checks defeats a freshness requirement. | **Misuse** if these conditions are violated; no HMAC or primitive break is demonstrated. |
